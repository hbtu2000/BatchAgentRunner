# 验收清单（Acceptance Checklist）

> 本清单依据 `samples/tasks.md` 中的任务指令生成，用于验收各任务的交付结果。
> 验收状态符号：☐ 未验收 / ☑ 已通过 / ☒ 未通过

---

## task-001

**指令：在 README.md 中补充「快速开始」章节**

- [ ] README.md 中新增了标题为「快速开始」（或英文 "Quick Start"）的章节
- [ ] 章节位置合理（建议在项目简介与安装说明之后、详细文档之前）
- [ ] 章节包含最小可运行的起步步骤（如安装、初始化、第一个命令/示例）
- [ ] 所列命令、路径、依赖与项目当前实际一致（无失效链接或错误示例）
- [ ] 示例可直接复制执行，无需额外未说明的前置条件
- [ ] 文档使用 Markdown 正确渲染（标题层级、代码块语言标识无误）
- [ ] 通过拼写与格式检查，无遗留占位文本（如 TODO / lorem ipsum）

## task-002

**指令：修复登录模块缺陷：**
1. 定位 `src/auth/login.ts` 的空指针风险并修复
2. 补充回归用例

- [ ] 已定位 `src/auth/login.ts` 中存在的空指针风险点（如未判空的对象访问、可能为 null 的返回值）
- [ ] 提交中说明了风险点的具体位置（文件、行号、触发条件）
- [ ] 修复方式合理（空值判空、默认值、可选链或类型收窄等），未引入新的类型/逻辑错误
- [ ] 修复后通过静态检查（编译器 / linter 无新增告警），未破坏现有类型签名
- [ ] 已补充至少一个针对该空指针缺陷的回归测试用例
- [ ] 回归用例能复现修复前的问题（在修复前该用例应失败，修复后应通过）
- [ ] 新增用例已并入测试套件并可在 CI / 本地 `npm test`（或对应测试命令）中运行通过
- [ ] 现有登录相关测试用例在修复后全部仍然通过（无回归）
- [ ] 相关改动有简短说明，便于审阅者理解修复动机

## task-003

**指令：为 `src/parser.ts` 补充单元测试**

- [ ] 为 `src/parser.ts` 新增了专用测试文件（如 `src/parser.test.ts` 或使用项目约定命名）
- [ ] 测试覆盖了主要公开函数 / 解析入口
- [ ] 包含正常输入的断言（正确解析、返回结构符合预期）
- [ ] 包含边界与异常输入的断言（空输入、畸形输入、超长输入等）
- [ ] 包含错误路径断言（解析失败时应抛出预期异常或返回预期错误）
- [ ] 测试用例命名清晰，能表达被测行为与预期结果
- [ ] 测试可独立运行且全部通过（无 flaky / 依赖外部状态）
- [ ] 测试覆盖了现有代码的主要分支（可通过覆盖率工具核验，目标覆盖率与项目约定一致）
- [ ] 已在 README 或贡献指南中确认测试运行方式，或沿用现有测试约定

## 通用验收要求（适用于全部任务）

- [ ] 所有改动未引入新的编译 / 构建错误
- [ ] 执行对应测试命令后整体结果通过（或失败项与本次改动无关且有说明）
- [ ] 无遗留调试代码、控制台垃圾输出或临时文件被提交
- [ ] 改动范围与对应任务指令一致，未夹带无关修改
- [ ] 提交信息（commit message）能清晰对应任务编号与目标
