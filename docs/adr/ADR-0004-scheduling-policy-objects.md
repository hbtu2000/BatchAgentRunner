# ADR-0004：调度策略对象化

- 状态：已接受（Accepted）
- 日期：2026-10-21
- 决策者：架构组
- 关联：ARCH P-03 / A-2；`src/BatchAgentRunner.Core/Scheduling/`

## 背景

任务重试链路上的四类判断（额度耗尽降级、冷却等待、兜底模型切换、时段窗口）原本内联在
`TaskRunner` 的深层嵌套分支里，且每类判断都夹带副作用（写状态、发事件、改计数器）。
后果：策略边界不可见、无法单测、改动一处容易影响另一处。

## 决策

1. 把四类判断抽为**无副作用策略对象**（纯函数 + 显式输入/输出）：
   - `DegradationPolicy`：额度/凭据失败后的降级与模型推进；
   - `CooldownPolicy`：冷却判定与到期计算；
   - `FallbackPolicy`：兜底模型序列的选择；
   - `FreeTimeWindowPolicy`：免费时段窗口判定（含跨零点）。
   同族另含 `RetryPolicy` / `QuotaWaitPolicy` / `SessionResumePolicy`。
2. 策略只回答「该不该、选哪个、等多久」，**不写状态、不发事件、不落盘**；副作用由 `TaskRunner` 统一执行。
3. `TaskRunner` 退化为「取决策 → 执行副作用 → 推进状态机」的薄编排（≤400 行）。
4. 每个策略有独立单测，覆盖边界（空序列、全冷却、跨零点、凭据失效等）。

## 后果

**正面**

- 策略可独立单测与组合，行为差异一眼可读；
- 降级/冷却/兜底/时段的规则修改不再牵动状态机；
- 「时段外/冷却跳过不计失败」等口径可被策略单测锁死。

**负面 / 代价**

- 增加了类型与调用层数；策略输入需完整（如需传入当前时间与冷却记录，而非内部读时钟）。
- 策略若需要新上下文，必须改签名并同步调用点，短期改动面变大。

## 替代方案

| 方案 | 为什么不选 |
| --- | --- |
| 保留内联分支 + 注释说明 | 边界仍不可测；四类判断互相纠缠，回归风险高 |
| 用 `if` 链聚合为一个「策略方法」 | 只是把大方法搬个地方，仍共享可变状态，无法单测 |
| 引入规则引擎 / DSL | 对四类规则属过度设计，调试与可读性反而下降 |
