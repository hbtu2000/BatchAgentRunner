## 3. v1.9 新特性审查：值得保持的设计

1. **两种不可用原因的分离建模（核心亮点）**：「免费时段外跳过」与「额度耗尽」被定义为独立原因——前者不发起调用、不计失败、不触发切换告警，后者触发切换与告警。该分离贯穿 REQ-003b/004/011、附录 B、埋点表与误切换率口径，确保「时段外跳过」不污染误切换率指标。这是调度类需求最容易混淆、本次处理得最干净的一点。
2. **waiting / blocked 分流合理**：全部模型时段外时，按「最长可等待时长（默认 60 分钟，可配置）」决定等待倒计时还是直接阻塞，避免了「为省几分钟费用让批处理空转」和「无谓阻塞」两个极端。
3. **在途任务不因时段边界中断**：任务启动后跨越时段边界不中断、不失败，完成后按新时段视图调度下一条——时段是调度维度而非执行约束，语义自洽。
4. **联动面无挂空**：时段特性与兜底触发条件（REQ-004b）、预检（REQ-010）、报告（REQ-011 三段区分 + 时段外等待时长统计）、并发（REQ-012 共享时段视图）、自动关机（REQ-015 排除 waiting）、边缘情况 12、UI 六状态与文案全部对齐，未发现「改了 A 忘了 B」式的悬挂引用。
5. **配置具体可验**：跨零点时段（22:00–06:00）、星期过滤、按本机挂钟时间判定均有明确定义，并给出了 JSON 配置示例。

## 4. 🟠 重要问题（Should Fix，M2 启动前必须闭环）

### R-1 候选模型配置项的 `account` 字段与「账号池 × 模型候选」矩阵语义冲突；免费时段粒度（按模型 / 按账号+模型）未定义

- **位置：** REQ-003b 配置示例、REQ-003、REQ-004、附录 B 状态机
- **问题：** REQ-003b 的配置示例中，候选模型项携带 `"account": "账号1"` 字段，暗示**模型与账号绑定**；但 REQ-003/004 与附录 B 将账号池与模型列表定义为两个独立维度，降级为全矩阵遍历（账号1+模型A → 账号1+模型B → … → 账号2+模型A），且「模型优先」策略（同账号先轮换候选模型）以模型列表跨账号共享为前提。二者不能同时成立：
  - 若 `account` 字段有效（模型可绑定账号），则附录 B 的矩阵遍历与「模型优先」策略需重写，候选列表实质变成「组合列表」；
  - 若无效，则该字段是示例笔误，会误导工程按错误的数据模型实现。
- **连带问题（时段粒度）：** 免费时段挂在模型项上，即**按模型**配置；但真实业务中免费额度时段通常是「账号 × 模型」属性（例如：账号1 的模型A 仅 08–12 免费，账号2 的模型A 全天免费）。按模型单点配置无法表达此类场景；若时段应按组合配置，附录 B「先过滤免费时段」的规则也需改为组合级过滤。
- **影响：** 配置数据模型是调度器与 CLI 适配层的输入契约，此处二义会直接导致实现分叉，且落在产品核心差异化机制（双维度降级）上。初核 B-1 已解决「执行语义」，本轮 R-1 解决「配置语义」，两者共同构成机制地基。
- **建议（二选一，全文统一）：**
  - **方案 ①（简化，推荐一期）：** 删除示例中的 `account` 字段，明示候选模型列表为账号无关的全局列表、免费时段按模型配置（同一模型在所有账号下时段一致）；
  - **方案 ②（表达力强）：** 定义「模型可绑定账号（可选字段）」+ 免费时段按「账号 × 模型」组合配置，同步修订 REQ-004 矩阵遍历规则、附录 B 状态机（时段过滤下沉到组合级）与故事 2.3 的「模型优先」定义。
  - 无论选哪种，请在 REQ-003b 配置示例处补一句字段级说明，并在 M0 结论中记录该决策。
