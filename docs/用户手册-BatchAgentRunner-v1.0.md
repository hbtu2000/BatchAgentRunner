## 一、这是什么

一句话：**把一堆任务丢进文件，程序自动逐条调用 AI CLI（CodeBuddy）干活，结果自动写回文件，额度用完自动换账号/换模型继续，全程有界面盯着，随时能停。**

适合的场景：批量改代码、批量生成文档、批量分析文件——凡是你要在 AI 助手里「逐条提交→等结果→复制回来」重复 N 遍的活。

## 二、安装与启动

**前置条件**：已安装 .NET 10 SDK（`dotnet --version` 能输出版本号）。

两种启动方式（在仓库根目录 `E:\Src\CodeBak\WorkAgent` 下执行）：

```powershell
# 方式 A：直接跑源码
dotnet run --project src/BatchAgentRunner.Desktop

# 方式 B：先构建出 exe，以后双击启动
dotnet publish src/BatchAgentRunner.Desktop -c Release -o publish
.\publish\BatchAgentRunner.Desktop.exe
```

程序是纯本地运行，不上传任何数据。配置文件在首次保存后生成于：

```
%LOCALAPPDATA%\BatchAgentRunner\config.json
```

## 三、第一次跑通（5 分钟，不装 CLI）

先用内置的 **Mock 仿真适配器**跑通全流程——它不调任何真实 CLI，专门用来验证调度逻辑（状态流转、结果回写、报告生成）。

1. **启动程序**，左侧导航进入「配置向导（首次推荐）」，按 6 步走完：
   - 执行工具：选 **Mock**
   - CLI 检测：可勾选「跳过检测」
   - 账号 / 模型：默认即可（Mock 下随便填）
   - 任务文件：选 `samples/tasks.json`
   - 点「保存配置并重建引擎」
2. **进入「执行监控」页**，点「启动前预检」→ 应显示「预检通过：2 条任务，待处理 2 条」。
3. 点「开始执行」→ 观察任务状态从 执行中 → 已完成。
4. 打开 `samples/tasks.json` → 每条任务的 `status` 已被回写成 `done`，`result` 里有内容。

跑通了？恭喜，工具本身没问题。接下来换真实 CLI 只需要改配置。

> 想多测点场景：`samples/tasks.testdata.json` 里预置了降级、时段、冷却、兜底等各种测试用例。

## 四、界面导览

左侧导航共 5 页：

| 页面             | 干什么用                                      | 什么时候去       |
| -------------- | ----------------------------------------- | ----------- |
| **配置向导（首次推荐）** | 6 步引导：执行工具 → CLI 检测 → 账号 → 模型 → 任务文件 → 保存 | 第一次用；或想推倒重配 |
| **执行监控**       | 预检 / 开始 / 终止 / 续跑，实时看每条任务状态、降级切换、冷却倒计时    | 每次跑批都在这     |
| **配置**         | 全部配置项分组编辑，支持「引导登录」账号凭证                    | 向导不够用时精细调参  |
| **登录**         | 傻瓜式登录：拉起 CLI 登录 → 检测凭证 → 存入账号池            | 新增文件型登录账号时  |
| **报告**         | 批次汇总统计（成功/失败/降级次数/耗时/费用估算）                | 批次结束后复盘     |

## 五、准备任务文件

### JSON 格式（推荐，可原地回写）

```json
[
  {
    "id": "task-001",
    "workspace": "",
    "instruction": "在 README.md 中补充「快速开始」章节",
    "status": "Pending"
  }
]
```

你只需要写 4 个字段，其余（`result`、`model_used`、`error` 等）是程序回写用的：

| 字段            | 必填 | 说明                                               |
| ------------- | -- | ------------------------------------------------ |
| `id`          | 是  | 任务标识，批内唯一即可                                      |
| `instruction` | 是  | 你要 AI 干的活，写成一句完整、可独立执行的指令                        |
| `workspace`   | 否  | 命名空间名（对应配置里的 `workspaces[].name`）或绝对路径；留空用默认工作空间 |
| `status`      | 否  | 写 `Pending` 或不写即可。**已 `done` 的任务默认跳过**——这就是断点续跑  |

### Markdown 格式（只读输入）

参考 [`samples/tasks.md`](../samples/tasks.md)：

```markdown
# Tasks

## task-001

- instruction: 在 README.md 中补充「快速开始」章节
```

Markdown 任务文件**不会被改写**，状态和结果写到旁边的 `tasks.md.result.json`。

> ⚠️ 每次启动前程序会自动备份任务文件（`tasks.json.backup-<时间戳>`，默认保留 5 份），放心折腾。

## 六、接真实 CLI（CodeBuddy）

### 1. 装 CLI

```powershell
npm install -g @tencent-ai/codebuddy-code
codebuddy --version   # 能输出版本号即可
```

（WorkBuddy 与 CodeBuddy 同用 `codebuddy` 命令，无需单独安装。）

### 2. 配账号（三选一）

| 你的情况                  | 怎么做                                                                                            |
| --------------------- | ---------------------------------------------------------------------------------------------- |
| **本机 CLI 登录的账号（最常用）** | 配置页该账号点「引导登录」，或用「登录」页一键完成。凭证快照存入本机 Vault（DPAPI 加密），明文不落盘                                       |
| **API Key 型账号**       | 先建系统环境变量 `XXX=你的Key`，账号的凭据引用填 `env:XXX`。程序会把 Key 以 `CODEBUDDY_API_KEY` 注入 CLI 子进程              |
| **多账号轮换**             | 点「添加备用账号」加多条。注意：同一台机器的 CLI 登录态只有一个，多条 `profile:default` 是同一身份——真正的多账号请用 env: API Key 或逐个「引导登录」 |

### 3. 配模型池

每个账号下配 **自己的候选模型列表**（按优先级排序）：

```json
{
  "id": "acc-1",
  "model_candidates": [
    { "name": "模型A", "free_time_window": null },
    { "name": "模型B", "free_time_window": { "start": "00:00", "end": "08:00" } }
  ]
}
```

- `free_time_window` 填了 = 免费时段，时段外自动跳过该模型；不填 = 全天可用
- 额度耗尽 → 自动切到账号内下一个模型 → 账号内全耗尽 → 切下一个账号（默认 `ModelFirst` 策略）

### 4. 预检验证

配置页保存后到监控页点「启动前预检」：逐个账号探测，探测失败的账号会被**自动停用**并给出警告，任务文件/工作空间有问题也会在这里拦住。

## 七、日常跑批流程

监控页 4 个核心按钮：

```
[启动前预检] → [开始执行] → 跑完看报告
                  │
                  ├─ 想中途停：点「终止」（当前任务立刻断）或「终止（等当前任务完成）」（更干净）
                  ├─ 想接着跑：再点「续跑」——已 done 的跳过，从断点继续
                  └─ 显示「等待恢复」中：等到点自动继续；等不及点「取消等待」转阻塞，手动续跑
```

**典型一天**：

1. 晚上把第二天要干的 50 条任务写进 `tasks.json`；
2. 打开程序 → 预检 → 开始执行 → 人走开；
3. 凌晨某个账号免费时段到了自动用上，额度耗尽自动换账号/换模型；
4. 早上回来看报告，个别 `failed` 的补一句 instruction 改完再「续跑」；
5. 想无人值守自动关机：配置里开 `auto_shutdown`（只在全部落盘、报告写完后才触发，并先弹 60 秒可撤销倒计时，点「取消关机」即可中止）。

**安全性说明**（无人值守的核心保险）：

- CLI 停下来等确认时，程序按黑/白名单自动应答：命中黑名单（`rm -rf`、`git push --force` 等 18 条）**绝不批准**，直接杀进程判该任务失败；
- 想加自己确认过的安全词：配置 `auto_answer.allowed_whitelist`（白名单优先于黑名单）。

## 八、跑完后去哪看结果

所有产物都在**任务文件同目录**：

| 产物   | 位置                                               | 内容                           |
| ---- | ------------------------------------------------ | ---------------------------- |
| 任务结果 | 任务文件本身（JSON）或 `<名>.md.result.json`（MD）           | 每条任务的 result、用的哪个账号/模型、耗时、错误 |
| 运行日志 | `runs/run-<时间戳>.log`                             | 全程事件流：降级切换、冷却、自动应答、警告        |
| 汇总报告 | `report-<时间戳>.json` / `.md`                      | 批级统计，可直接给人看                  |
| 任务备份 | `<任务文件>.backup-<时间戳>`                            | 启动前快照，改坏了能回滚                 |
| 程序配置 | `%LOCALAPPDATA%\BatchAgentRunner\config.json`    | 持久配置                         |
| 冷却记录 | `%LOCALAPPDATA%\BatchAgentRunner\cooldowns.json` | 额度冷却跨重启有效；误记了可在监控页「重置冷却」清空   |

## 九、关键概念 3 分钟速览

- **降级矩阵** = 各账号 × 各自的候选模型池。一个「账号 × 模型」组合可用，当且仅当：在免费时段内 **且** 不在额度冷却中。
- **额度耗尽怎么判定**：靠 CLI 报错文本关键词匹配。解析不到重置时间就按 `default_cooldown_minutes`（默认 60 分钟）冷却。
- **时段外跳过 / 冷却跳过 ≠ 失败**：这是预期的调度行为，不计入失败。
- **waiting vs blocked**：所有组合暂不可用、但最早恢复时间在 `max_wait_minutes` 内 → **等待恢复**（自动）；超出 → **已阻塞**（需要你补额度/加账号后手动续跑）。
- **兜底模型**（默认关闭）：某任务已经开跑、免费组合又全不可用时，用账号的 `fallback_models` 付费收尾。有单任务/整批两层花费上限。
- **切换 = 全新会话**：换组合后按任务完整指令重新执行，不继承上一次上下文。

## 十、常见问题

完整版见 [`CONFIG-配置项说明.md` 第 4 节](CONFIG-配置项说明.md)，最高频的几条：

| 现象             | 处理                                                   |
| -------------- | ---------------------------------------------------- |
| 点「开始」没反应       | 任务文件路径没选，选上即可                                        |
| 预检报「工作空间目录不存在」 | 配置里的目录路径写错了，改对再跑（有意拦截，防止 AI 在错误目录乱改文件）               |
| 所有任务都提示时段外     | 检查模型的 `free_time_window`，不在窗口内会被跳过；不想要时段就删掉该字段       |
| 明明有额度却提示冷却中    | 上次的 `cooldowns.json` 还在生效，监控页「重置冷却」清掉                |
| 改了配置不生效        | 账号/模型/时段/降级策略必须重建引擎：界面点「保存配置并重建引擎」；手改文件则重启程序         |
| 配置文件里的注释不见了    | 界面保存会重写文件丢注释，注释版模板以 `samples/config.example.json` 为准 |
| 危险操作被拦、任务判失败   | 黑名单安全阀，有意为之；确认安全就加白名单                                |
| 兜底没触发          | 免费组合一次都没用过时不会兜底（只在「已投入执行」的任务上兜底）                     |
