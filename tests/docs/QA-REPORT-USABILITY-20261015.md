# 可用性测试报告 · BatchAgentRunner v1.0

- 日期：2026-10-15
- 范围：首次启动体验 / 配置可改性 / 预检指引 / 文档「5 分钟跑通」/ 运行期操作（等待·取消·终止·重置冷却·兜底）/ GUI 交互点
- 方法：引擎级用户旅程场景测试（Mock 适配器）+ GUI 静态走查（AXAML/ViewModel 对照文档口径）
- 产物：`tests/BatchAgentRunner.Tests/Usability/UsabilityTests.cs`（9 个用例，TC-UX-001~009）

## 1. 结论

**总体可用性良好，可支撑新用户照文档独立走通全流程。** 构建 0 错误；测试 74/74 通过（既有 65 + 新增 9）。
发现 1 项中等可用性风险（F1：坏配置静默重置）与若干低风险/信息项，均不阻塞使用。

## 2. 场景结果

| 用例 | 场景（用户旅程） | 结果 |
|------|------|------|
| TC-UX-001 | 首次启动无 config.json | ✅ 示例配置结构完整（2 账号/2 模型/默认工作区）；预检报「未选择任务文件」明确指引下一步 |
| TC-UX-002 | 手改配置写坏 JSON | ✅ 不崩溃、回退示例配置；磁盘坏文件不被覆盖 | 
| TC-UX-003 | 多项配置缺失 | ✅ 预检一次性收集全部中文指引（任务文件/账号池/候选模型），不抛异常 |
| TC-UX-004 | 使用仓库样例文件 | ✅ `samples/tasks.json`（2 条）与 `samples/tasks.md`（3 条）均可被 TaskFileStore 解析，无告警 |
| TC-UX-005 | 照文档「5 分钟跑通」Mock 全流程 | ✅ 预检文案与文档逐字一致（"预检通过：2 条任务，待处理 2 条"）；开始执行后全部回写 done |
| TC-UX-006 | 组合从未开跑过时兜底 | ✅ 不误触发兜底，直接阻塞（与文档 §3.5/坑表一致），零 CLI 调用 |
| TC-UX-007 | 等待恢复中手动取消 | ✅ 转 blocked，任务保留 pending，事件提示「等待被取消」 |
| TC-UX-008 | 额度耗尽 → 重置冷却 → 续跑 | ✅ 冷却 90 分钟（> max_wait 60）转阻塞；点「重置全部冷却」+「续跑」后同引擎恢复执行成功 |
| TC-UX-009 | 运行中点「终止」 | ✅ 批转 Terminated；当前任务安全中断；未跑任务保留 pending，结果不丢 |

边界备注（TC-UX-008 推导）：冷却时长 **≤** max_wait 时走「等待恢复」自动续跑而非阻塞（60min 冷却 == 60min max_wait 即等待）——与文档 §3.2 语义一致，非缺陷。

## 3. GUI 走查（对照 docs/CONFIG-配置项说明.md）

- 监控页按钮齐备且与文档口径一致：加载任务文件 / 启动前预检 / 开始执行 / 续跑 / 终止 / 终止（等当前任务完成）/ 取消等待（仅等待态可见）/ 重置全部冷却。
- 「开始执行」在 `task_file_path` 为空时禁用（坑表第 1 条吻合）；`CanStart/CanResume/CanTerminate` 随运行状态联动。
- 预检/加载/执行异常均以状态栏中文消息呈现，不弹异常堆栈。
- 配置页「保存配置并重建引擎」：字段收集（数值有下限钳制：并发≥1、重试≥0、超时≥1 等）→ 落盘 → 重建引擎 → 反馈消息，与文档 §0「保存会自动重建」一致；ToolTip 已提示保存丢注释。

## 4. 发现与建议

| 编号 | 严重度 | 发现 | 建议 |
|------|--------|------|------|
| F1 | 中 | `JsonConfigStore.LoadAsync` 遇坏 JSON **静默回退示例配置**（`JsonConfigStore.cs` catch JsonException → CreateSample）。用户手改文件写坏一个逗号 → 界面上账号/模型等自定义全部消失且无任何告警 | 加载失败时向用户发出明确警告（如状态栏/标题栏提示「配置解析失败，已临时使用示例配置」），并提示坏文件路径 |
| F2 | 低 | 配置页仅能编辑白名单；**危险操作黑名单 / default_answer / stdin_idle_seconds 无 UI 入口**。文档 §⑨「误判了就在这里补词」未说明 UI 不支持黑名单编辑 | 补 UI 字段，或文档注明需手改 config.json + 重启 |
| F3 | 低 | `TaskFileStoreTests` 存在 9 个 xUnit1031 分析器警告（阻塞等待） | 改 async 测试方法 |
| F4 | 信息 | 文档坑表按钮名「重置冷却」vs 实际按钮「重置全部冷却」 | 文档措辞对齐 |
| F5 | 信息 | 冷却 ≤ max_wait 走等待恢复路径（含 60==60 边界） | 语义正确，建议文档 §3.2 增补边界示例 |

## 5. 测试边界（诚实声明）

- 全部场景基于 Mock 适配器：验证调度/降级/冷却/兜底/危险拦截与文件回写，**不验证真实 CLI 输出质量**（M0 V-1~V-10 项除外，与既有 E2E 口径一致）。
- GUI 走查为静态核对（AXAML/ViewModel/文档三方对照），未做真人点击走查；建议后续补一次 5 分钟跑通的手工实走。
- 测试执行环境：Windows / net10.0 / xUnit。
